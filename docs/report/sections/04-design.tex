\subsection{Key decisions}

\begin{center}
\small
\begin{tabularx}{\textwidth}{@{}>{\raggedright\arraybackslash}p{0.26\textwidth}>{\raggedright\arraybackslash}X@{}}
\toprule
\textbf{Decision} & \textbf{Reasoning} \\
\midrule
\textbf{OGC API --- Processes}, not WPS
  & The modern successor: JSON over REST, a real job model, an OpenAPI
    description. The standard a new service in 2026 should implement. \\
\textbf{pygeoapi}
  & Reference implementation of the OGC API family, so conformance comes from
    the framework rather than hand-rolled routing. Compliance carries the most
    marks; hand-rolling a job API to spec is the wrong risk. \\
\textbf{Greedy set cover}
  & Set cover is NP-hard~\cite{setcover}; greedy is within a $\ln(n)$ factor of
    optimal, fast enough for a synchronous request, and yields a
    \emph{cumulative coverage curve} --- more useful than a bare optimal set,
    because it shows what each extra scene buys. The response declares the
    algorithm and its bound, so no client mistakes it for a proven minimum. \\
\textbf{TinyDB job manager}
  & Jobs persist, so async execution survives a restart and \ep{/jobs/\{id\}}
    keeps working. PostgreSQL in production. \\
\textbf{Native deployment}
  & The build host's user was not in the \code{docker} group and no sudo
    password was available, so the native path is the tested one and is
    labelled as such. \\
\bottomrule
\end{tabularx}
\end{center}

\subsection{Areas are measured in an equal-area projection}

Every area in every response is computed in a \textbf{Lambert Azimuthal
Equal-Area} projection centred on \emph{that request's own} AOI:

\begin{lstlisting}
+proj=laea +lat_0=<aoi centroid lat> +lon_0=<aoi centroid lon>
+datum=WGS84 +units=m +no_defs
\end{lstlisting}

This matters more than it appears. The whole service answers area-based
questions --- how much is covered, what is the gap, which scene adds most.
Computing those in degrees would make every number meaningless, and
\emph{silently} so. Centring per request keeps distortion negligible for an AOI
of any size anywhere in India. A test asserts that a
$0.5^\circ\times0.7^\circ$ AOI reports thousands of km\textsuperscript{2}
rather than a fraction, so this cannot regress unnoticed.

\subsection{Provenance is declared in-band}

Every response carries a \code{provenance} block stating how many footprints
were considered, the filters applied, the area CRS, and --- critically ---
whether the footprint store is Bhoonidhi's or a substitute
(\code{is\_substitute\_for\_bhoonidhi}). This is a design decision, not a
disclaimer bolted on: a spatial analysis service whose inputs are unclear is
worse than none, because its outputs look authoritative.

\subsection{Authenticating against Bhoonidhi}

Every Bhoonidhi data endpoint is session-gated, and hitting one without a
token returns the error most users meet first:

\begin{lstlisting}
GET https://bhoonidhi-api.nrsc.gov.in/download
{"ErrorCode":"401","Description":"UNAUTHORIZED",
 "Action":"Invalid session detected! Please login again."}
\end{lstlisting}

That is correct behaviour, and Section~\ref{sec:gap} is explicit that the gap
identified here is about computation rather than access. But it makes login
the first thing that can fail, and probing the live API showed three problems
worth fixing rather than documenting away:

\begin{enumerate}[leftmargin=1.8em,itemsep=0.4ex]
  \item \textbf{Session exhaustion.} Each harvest authenticated afresh.
        Bhoonidhi limits concurrent sessions, so repeated runs eventually
        return \code{HTTP 403} and lock the account out until the old sessions
        expire --- a failure that appears only after the code has been working
        for a while.
  \item \textbf{Opaque failures.} Bhoonidhi returns bare status codes with the
        genuinely useful text in the body's \code{Action} field, which the
        client discarded.
  \item \textbf{No way to test credentials} short of running a whole harvest.
\end{enumerate}

\code{scripts/bhoonidhi\_login.py} addresses all three: one login, a token
cached \code{0600} under \code{runtime/} and reused by the harvester, a real
\ep{/auth/logout} to release the session, and errors that quote Bhoonidhi's
own message back to the user. It also \emph{verifies} the token against
\ep{/data/collections} rather than trusting that a 200 on \ep{/auth/token}
means anything.

\begin{lstlisting}
$ make login
  fail  Bhoonidhi rejected the request: Bad Request - Improper inputs
        specified. Please give correct inputs

  BHOONIDHI_USER must be the user id chosen at registration,
  which is not always your email address.
\end{lstlisting}

That last trap --- user id versus email --- produces an \code{ErrorCode 400}
that reads like a client bug and is not. The password is read from the
environment or \code{.env}, never from argv (world-readable in \code{/proc}),
never printed, and sent only to \code{bhoonidhi-api.nrsc.gov.in} over HTTPS.

\textbf{No account is needed to run or mark this project.} The shipped store
uses a public STAC substitute; the service, all 135 tests and the whole
demonstration work with no credentials. Credentials only swap the substitute
for real Bhoonidhi data.

\subsection{Defects found during development}
\label{sec:defects}

Recorded because they are the part of the work that was actually difficult, and
because a compliance suite that never caught anything is not evidence of much.
Each is now guarded by a test.

\paragraph{1. Every execution returned HTTP 400 after a reboot.} pygeoapi's
TinyDB job manager writes results into \code{output\_dir} and \textbf{does not
create it}. The path was under \code{/tmp}, which the OS clears. It existed
during the session it was created in, so everything passed; after a reboot every
\code{POST .../execution} failed with an opaque \emph{``No such file or
directory''}. This took \textbf{39 of the 100 tests} down at once. The job store
now lives under \code{runtime/jobs} via a \code{\$\{JOBS\_DIR\}} substitution
that \code{serve\_local.sh} creates before starting gunicorn.

\paragraph{2. A hairline sliver reported as a gap alongside
\code{fully\_covered: true}.} Differencing near-identical polygons leaves
slivers of effectively zero area, producing self-contradictory output. Anything
under 0.01\,km\textsuperscript{2} now collapses to no gap, the threshold is
published as \code{gap\_threshold\_km2} so it is inspectable rather than magic,
and a test asserts the two can never coexist.

\paragraph{3. The zero-footprint branch returned a different JSON shape.} When
nothing matched, \code{aoi-coverage} returned different keys from the populated
case --- breaking any client the first time a search came back empty. Both
branches now share one schema; a test asserts it.
