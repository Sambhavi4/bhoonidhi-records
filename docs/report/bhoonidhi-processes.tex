\vspace{1.4cm}
\begin{minipage}{0.86\textwidth}\small
\textbf{Abstract.} Bhoonidhi, ISRO's national remote sensing data
repository, publishes a competent STAC-based discovery API: a client can
authenticate, search by space and time, and download products by identifier.
It stores the footprint polygon of every scene it holds. This report shows
that the \emph{only} question a user may ask of that geometry is whether it
intersects theirs --- the portal's entire spatial surface is \code{bbox} and
\code{intersects}, one predicate expressed two ways, with no analysis
vocabulary anywhere in the specification and no processing endpoint anywhere
in ISRO's public stack. The consequence is measured rather than asserted:
across eight queries the catalogue returns \textbf{208 scenes where 16 cover
the same ground to the same percentage}, so \textbf{92\,\% of what a user is
told to download is redundant}, and nothing in the API lets them discover
that. Server-side geospatial computation has been an OGC standard since 2007;
the Copernicus Data Space publishes 146 such processes at a public endpoint
while Bhoonidhi publishes none. The gap is therefore an absent \emph{tier},
not a missing parameter. This report documents the design, implementation and
compliance testing of a conformant \textbf{OGC API --- Processes} service
(pygeoapi, shapely) exposing six spatial operations over acquisition
footprints and the raster values beneath them, with synchronous and
asynchronous execution, a job API, and all areas measured in an equal-area
projection. \textbf{All 100 compliance tests pass}, and the suite verifies the
mathematics --- that covered plus gap reconstructs the area of interest, that
an intersection never exceeds its operands, that greedy coverage is monotonic
--- not merely the protocol shape.
\end{minipage}
